# Rattil · رتّل

A free, open-source, ad-free Android mushaf that listens while you recite.

Tap the microphone and start reciting from anywhere in the Quran. Rattil works out where you are, opens that
page of the 604-page Madani mushaf, highlights the ayah you are on, follows you word by word and turns the
pages as you go. Possible memorization mistakes (a wrong, missed or extra word, or a skipped passage) are marked
gently with a soft underline, never by changing the text.

Recognition runs entirely on the phone with [Tilawa](https://github.com/yazinsai/tilawa). Your voice is never
recorded, stored or sent anywhere.

## Download

Get the latest APK from [Releases](https://github.com/amaan-argaam/rattil/releases). The first time you tap the
microphone, the app downloads Tilawa's recognition model (25 MB) once from tilawa.dev; after that it works
offline. A more accurate 68 MB model can be switched on in the index screen.

## Features

- 604-page Madani layout, 15 lines per page, with the classic page and line breaks
- Uthmani script (Tanzil text, verbatim) set in Amiri Quran
- Cream paper, ornamental page frames, decorated surah headers and ayah rosettes
- Right-to-left page swipes, surah and juz index
- Night mode
- Follows your recitation and turns pages; marks possible mistakes gently

## How it works

| Part | What |
|---|---|
| `src/engine/recitation.ts` | Mic (react-native-audio-api, 16 kHz) → Tilawa free-recitation session on onnxruntime-react-native → current word and confirmed mistakes |
| `src/engine/assets.ts` | One-time download of the model and reference from `https://tilawa.dev/v1/`, verified against the sha256 in Tilawa's registry |
| `src/data/` | Text, page layout and metadata, generated by `scripts/build-quran-data.mjs` |
| `src/ui/` | The mushaf page, ornaments, index and About screens |

Tilawa reports positions as `{ surah, ayah, word }`. The build script checks that Tanzil's words (with pause
marks attached to their word) line up one-to-one with Tilawa's reference for all 6,236 ayahs, so highlights land
on the right word.

### Rebuilding the Quran data

```bash
./scripts/fetch-sources.sh          # Tanzil text + metadata, DigitalKhatt line breaks → data-src/
node scripts/build-quran-data.mjs   # → src/data/generated/*.json (validated)
```

## Building

```bash
npm ci
npx expo prebuild -p android
cd android && ./gradlew assembleRelease
```

Without signing variables the release APK is signed with the debug key. To sign, set `RATTIL_KEYSTORE`,
`RATTIL_KEYSTORE_PASSWORD`, `RATTIL_KEY_ALIAS` and `RATTIL_KEY_PASSWORD` (see `plugins/with-release-signing.js`).

### Releases

Pushing a tag `vX.Y.Z` (matching `version` in `app.json`) runs `.github/workflows/release.yml`, which builds a
signed APK and publishes it as a GitHub pre-release. It needs these repository secrets:

- `RATTIL_KEYSTORE_BASE64`: the keystore, base64-encoded
- `RATTIL_KEYSTORE_PASSWORD`: its password (also used as the key password)
- `RATTIL_KEY_ALIAS`: the key alias

The keystore is never committed.
